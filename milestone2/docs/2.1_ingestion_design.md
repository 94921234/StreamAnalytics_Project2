# Milestone 2.1 — Ingestion Design: Azure Event Hubs

## Overview

This document describes the Azure Event Hubs ingestion design for the two streaming feeds
of Group 04's food delivery platform (Madrid). All data is produced by the Python generator
(`generator/`) and streamed via `EventHubProducerClient` to the namespace
`iesstsabbadbab-grp-01-05`.

---

## Event Hub Namespace

| Parameter        | Value                          |
|-----------------|-------------------------------|
| Namespace        | `iesstsabbadbab-grp-01-05`    |
| Resource Group   | `SA_BBADBA2025NBDA_B`         |
| Region           | West Europe                   |
| SKU              | Standard (throughput units)   |

---

## Event Hubs (Topics)

### 1. `group04_orders` — Order Events

| Parameter          | Value / Rationale                                              |
|-------------------|---------------------------------------------------------------|
| **Partitions**     | 3                                                             |
| **Partition Key**  | `zone_id`                                                     |
| **Retention**      | 1 day (default)                                              |
| **Message format** | JSON (UTF-8 encoded)                                         |

**Partition key rationale:** Using `zone_id` as the partition key ensures that all order
events for the same geographic zone land in the same partition, enabling ordered,
zone-level stream processing. This is critical for Use Cases 2 and 3 (demand/supply
balance and surge detection per zone).

**Expected throughput:**
- Generator produces ~50–200 order events/minute depending on simulation hour (peak lunch/dinner).
- Average message size: ~400 bytes (JSON with all fields).
- Peak throughput: ~200 msgs/min × 400 B ≈ ~80 KB/min → well within Standard SKU limits.

**Consumer groups:**
- `$Default` — used by Spark Structured Streaming (main pipeline).
- `monitoring-cg` — reserved for future monitoring/alerting consumer.

---

### 2. `group04_courierevents` — Courier Events

| Parameter          | Value / Rationale                                              |
|-------------------|---------------------------------------------------------------|
| **Partitions**     | 3                                                             |
| **Partition Key**  | `zone_id`                                                     |
| **Retention**      | 1 day (default)                                              |
| **Message format** | JSON (UTF-8 encoded)                                         |

**Partition key rationale:** Same `zone_id` strategy as orders ensures that for any given
zone, both order and courier events land in the same partition number. This aligns the
two streams by zone for efficient stream-stream joins in Spark without cross-partition
shuffling.

**Expected throughput:**
- Generator produces ~30–120 courier events/minute (online/offline, movement, assignment).
- Average message size: ~350 bytes (JSON with lat/lon, status, etc.).
- Peak throughput: ~120 msgs/min × 350 B ≈ ~42 KB/min.

**Consumer groups:**
- `$Default` — used by Spark Structured Streaming (main pipeline).
- `monitoring-cg` — reserved for future monitoring/alerting consumer.

---

## Consumer Group Strategy

| Consumer Group   | Used By                          | Purpose                                   |
|-----------------|----------------------------------|------------------------------------------|
| `$Default`       | Spark Structured Streaming       | Main analytics pipeline (2.2 + use cases)|
| `monitoring-cg`  | Future monitoring agent          | SLA alerts, anomaly detection alerts     |

**Rationale:** Event Hubs consumer groups provide independent read cursors (offsets),
allowing multiple consumers to read the same stream independently without interference.
The Spark pipeline uses `$Default` to avoid creating unnecessary consumer group overhead
during development.

## Message Sizing and Throughput Summary

| Feed                   | Avg Msg Size | Peak Rate      | Peak Throughput |
|-----------------------|-------------|---------------|-----------------|
| `group04_orders`       | ~400 B       | ~200 msgs/min  | ~80 KB/min      |
| `group04_courierevents`| ~350 B       | ~120 msgs/min  | ~42 KB/min      |
| **Total**              |             |               | **~122 KB/min** |

Standard SKU supports up to 1 MB/s per throughput unit — our load is well within limits.
